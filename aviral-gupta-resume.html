E2E Test Platform & CI/CD
  • Migrated the slow, flaky WebdriverIO suite to Playwright. WDIO had piled up wrappers and a CJS teleport framework that transpiled our ES specs, which made builds slow, and its reports needed a script just to attach logs and had no timeline view. Playwright brought native ES, much easier debugging, CDP execution (~2x faster than WDIO's ChromeDriver hops), and agent-scaffolded specs that cut new-spec authoring ~80% (~1 story point → ~30–60 min).
  • Designed the framework to be modular and scalable, keeping the core offerings (hydration, selective test execution, ticket creation, and performance checks) in a standalone automations package that any project can drop in through an agent.
  • Built change-based selective execution so a PR runs only the specs that exercise its changed code. E2E specs don't import source directly, so the mapping is derived from coverage: each run's V8 coverage gives the compiled chunk names, which resolve through source-maps back to the executed source lines, producing a reverse source-to-spec map that selects specs when their files change. This catches ~90% of leaked mainline bugs on the PR itself.
  • Fixed flaky Windows E2E runs caused by a Cloudflare allowlist race condition: an AWS Lambda and SQS pipeline registers each runner's dynamic IP before its run and clears it afterward.
AI & Agentic Test Tooling
  • Built an MCP server and daily LLM agents that tell real product bugs apart from flaky failures, auto-fix the test-side ones, and trace each failure back to the PR that caused it with a plain-English log summary. This took most of the manual triage that used to stall PRs and releases off the team's plate.
  • Designed E2E Coverage Signals, a dashboard that maps where customers actually feel pain (from GitHub, customer escalations, incident.io, and Slack) against our E2E coverage and ranks the riskiest gaps with a transparent scoring formula. A daily AI agent feeds the deterministic Node pipeline behind it, shipped as a React/Vite app on GitHub Pages. It gave leadership their first clear read on which important areas are under-tested.
Coverage & Quality Governance
  • Shipped an incremental-coverage check across all backend repos as a reusable GitHub Action that tells authors whether their actual change is tested, not just where total coverage sits. Lifted company-wide unit and integration coverage from 51% to 73% in 3 months.
